# 轮腿机器人差动腿长与支撑力控制规划

这份文档回答一个问题：**怎么让底盘在左右轮接地面不等高时保持 Roll≈0**，以及这件事要分几步做、每步落在哪个文件、拿什么验收。

依据是当前源码，不是构想。符号、路径、结论都从工作区现取。

---

## 1. 对照现状：哪些已经有了，哪些没有

### 1.1 Roll→左右腿差动：已经是 LQR，不是串级 PD+IK

现成的东西在 `project/node/chassis/roll_lqr.hpp`：

- 状态 `X = [q_h−, q̇_h−, q_k−, q̇_k−]`（`kStateDim = 4`）
- 输入 `U = [τ_h−, τ_k−]`（`kInputDim = 2`）
- 控制律 `U = U0 − control_sign · K · (X − X0)`，带工作点偏移
- 差模量的定义在 `chassis.hpp`：`hip_difference = 0.5(q_hL − q_hR)`、`knee_difference = 0.5(q_kL − q_kR)`
- 增益随腿高调度：`params/leg_gain/*.yaml` 六个工作点插值（`LqrGainSchedule`）

所以"Roll → 左右腿差动"这条路已经通了，而且比串级版本更进一步：LQR 自己决定髋和膝各出多少力（`R = [τ_h−, τ_k−]` 的权重就是在调这个分工）。

### 1.2 但现在的 Roll 环管的是"两腿一样长"，不是"机身水平"

这是最关键的一条差异。`RollLqrController::update()` **没有参考输入**（Pitch 那个有 `target`），也就是说它的 Xref 恒等于 X0 = 0：

```cpp
RollState roll_state;
roll_state << hip_difference, hip_difference_rate, knee_difference, knee_difference_rate;
RollControl leg_difference = roll_lqr_.update(roll_state, control_.control_sign);   // 没有 Xref
```

后果：环把 `L_L − L_R` 稳到 0。平地等价于机身水平；**斜面上机身会跟着坡一起歪**——右轮站高 5 cm，两条腿一样长，机身就斜 5 cm 对应的那个角。

`state_.roll` 确实测了（`on_imu`），但只用在两处，都是诊断：

- `predict_roll()` / `predict_roll_rate()` 拿差模角预测 Roll，日志里打"预测/残差"
- 日志行里的 `state_.roll` 本身

**没有一处把 φ 用进控制律。** 所以你要的"φ≠0 → 腿差动 → φ→0"这条环，现在缺的正是"把 φ 接进去"这一步。

### 1.3 φ 为什么当初没进状态（这条约束还在）

`on_imu` 的注释写着：Roll 四状态模型已消去这个约束坐标，这里用于安全和闭链一致性诊断。

原因：闭链腿机构里 φ 与腿差**代数相关**（腿差定了、地面高度差定了，φ 就定了），不是独立状态。硬把 φ 并进 A 阵会造出零特征值/不可观对，离线线性化的检查也过不去。所以后面 §4 的做法是**用 φ 生成差模参考**，而不是把它塞进状态向量。

真正不可测、也真正在捣乱的是那个**地面高度差 `d = z_R − z_L`**：它把 φ 和腿差的零点搬走。稳态满足 `φ = 0` 时腿差并不为 0，而是等于 `d/2`。

### 1.4 平均腿长 L+ 已经有了，差模腿长 L− 没有显式存在

`project/node/chassis/leg_height.hpp` 提供共模那一维：

- `h = 2·L·sin(α + q_h+)`，膝被 `q_k+ = −2·q_h+` 锁死
- 髋膝软限位换算出的可达高度区间（启动时打印）
- `move_towards()` 把目标高度按 `height_rate_mps` 折成缓坡

它的类注释写得很明确："本类只处理左右腿共同运动的共模坐标；左右腿高度差和 Roll 差模不在这里计算。"

所以 `L− = (L_L − L_R)/2` 现在只隐含在关节差模里，没有一个显式的量，也没有"L− 该是多少"的目标。

### 1.5 没有支撑力分配

现在跟支撑力沾边的只有 `project/node/chassis/leg_gravity_compensation.hpp`，它算的是**静态重力前馈**，而且法向力写死成两腿平分：

```cpp
const double normal_force = 0.5 * (model_.body_mass + 2.0 * height_.wheel_mass) * model_.gravity;
```

这就是一个矢状面 `τ = JᵀF` 的静态特例。斜坡上两腿载荷不同（甚至一侧离地）时，它仍然各算一半——离地判断和载荷分配都没有。

### 1.6 没有腿端虚拟坐标，也没有 α 这一维

腿端位置现在只有"高度"一维（共模）；差模是关节角。轮子的前后位置（连杆摆角 α）没有独立的控制量，它是髋膝共模 + 差模共同决定的副产品。

分配器 `project/node/chassis/torque_allocator.hpp` 做的是**执行器级**的裁剪（共模优先、成组限幅、变化率、软限位），输入是六路共模/差模力矩，不是"力级"分配。

### 1.7 现成可复用的两件"雅可比"

- 增益文件里存着 `roll_per_q`，即 `d(roll)/d[q_h−, q_k−]`，已经加载进 `RollLqrController::Parameters::GeometryRow`，`predict_roll()` 就在用它。
  nominal 那份的值是 `[-3.15e-9, -1.95]`——**髋差模对 roll 几乎零灵敏度，起作用的是膝差模**。这一条直接影响 §4 阶段 A 怎么把 φ 折成腿差。
- 离线工具里已经有一套雅可比做法可以照搬：COM 位置雅可比（中心差分，`generate_wheel_leg_lqr.cpp` 里 `com_jacobian`）和解析的 Roll 雅可比（`RollJacobian`）。运行时要用 JᵀF 的话，同一套算法可以搬进 `project/`。

## 2. 目标与边界

**这一轮要做的**

1. 斜面上机身保持水平（φ 稳态 < 1°），两腿自动一长一短
2. 支撑力按实际载荷分配，不出现"位置对了但一轮离地"
3. 腿端控制量从"关节角"上升到"腿端坐标"，为后面的 VMC/全身控制留接口

**这一轮不做的**

- 不做完整 WBC（14×6 统一 LQR）——那是 §4 阶段 E 的评估项，不是这一轮
- 不推翻现有 Roll LQR 换成串级 PD+IK：串级版本要丢掉的正是 LQR 的髋膝分工，属于倒退
- 不动模型（`robot/models/**`），参数冲突一律以模型为准

## 4. 分阶段

### 阶段 A：φ 进环（最小改动，先把斜面上的水平做出来）

**做法**：不给 Roll 环换架构，只给它加一个 Xref。Pitch 环已经是这个形状（`pitch_lqr_.update(state, target, feedforward, control_sign)`），Roll 照抄。

目标腿差（期望的差模角）：

```text
φ_err  = φ_ref − φ                      # φ_ref 通常为 0
ΔL*    = −(K_p·φ_err − K_d·φ̇)           # 期望的"左右腿长差的一半"
Δq_h−  = ΔL* · dq_h/dL                  # 由当前腿高的几何反算，dq_h/dL 现成
Δq_k−  = −2 · Δq_h−                     # 膝被 q_k = −2 q_h 锁死
RollXref = [Δq_h−, 0, Δq_k−, 0]
```

`dq_h/dL` 不用另写：`LegHeightKinematics` 用的就是 `h = 2L·sin(α+q_h+)`，在当前工作点求导即可（也可以同样按"共模工作点"预存进增益文件，跟 K/X0/U0 一起调度）。

**另一条等价路径**：直接用现成的 `roll_per_q` 反解——`Δq− = φ_err / roll_per_q` 取伪逆。这条更短，但要注意 nominal 下 `roll_per_q[0] ≈ 0`（髋差模对 roll 没灵敏度），实际会全压到膝差模上。两条路先算出来对比一下再定用哪条，别直接选。

**要改的接口**：`RollLqrController::update()` 现在只有 `(state, control_sign)`，加 `(state, target, control_sign)`，内部照 Pitch 的写法用 `U = U0 − control_sign·K·(X − Xref)`。

**必须先做的标定（开环，别直接闭环）**：

1. 固定腿差、量 φ：给 `Δq_k−` 一个已知的常数偏置（比如按 `roll_per_q` 折出 0.05 rad 腿差），看实测 φ 的符号和大小。这一步同时验证三处符号是否对齐：IMU 的 φ 符号、`roll_per_q` 的符号、`leg_joint_sign`。
2. 平地验证：`φ_ref = 0` 时新加的参考量应当恒为 0，行为跟改之前逐位一致（可以录包对比）。
3. 台阶验证：一侧轮下垫块（5 mm、10 mm 两档），看机身能否回平、腿差方向是不是"高的一侧腿短"。

**验收**：台阶上 φ 稳态 < 1°；腿差符号正确；平地静止波形与改之前一致；六路力矩不因此打到限幅（用 `力矩分配：…` 告警判断）。

### 阶段 B：地面高度差估计与限幅

`d = z_R − z_L` 不可测，但它可以估：稳态下 `d ≈ 2·(L_L − L_R)`（即两倍的腿差），此时 `φ ≈ 0`。做法：

- 用一个低通/慢积分从"稳态腿差"里估 d，作为前馈加到阶段 A 的 `ΔL*` 上，让环不用靠持续的 φ 误差去顶；
- 给 `ΔL*` 加限幅（对应软限位可达的腿差范围），够不到就停在那儿并报警，而不是把腿怼到软限位；
- 判断一侧离地：`state_.leg_valid`、关节力矩接近 0、或 φ 与腿差的预测关系破裂（`predict_roll` 的残差突然变大）——残差这条现成的，日志里已经在打。

**验收**：台阶上加前馈后 φ 的稳态误差比阶段 A 小；腿差不超过软限位；残差异常时能报出来。

### 阶段 C：支撑力分配

把"两腿平分"改成按实际载荷分：

```text
F_zL + F_zR = m·g
# 分配依据：质心横向位置 + 地面高度差 d（阶段 B 估出来的）
```

最小一版可以先按 d 或按 φ 的慢分量做线性分配（`F_zR = 0.5·mg·(1 + k·d)`），改进 `LegGravityCompensation` 里 `normal_force` 那一行，把系数参数化进 `chassis.yaml`。第二版再考虑用轮子接触/关节力矩做闭环估计。

**验收**：台阶上两轮的支撑力估计之比与理论比值（按质心位置算）相符；不出现"机身平了但一轮空转"。

### 阶段 D：腿端坐标与 JᵀF 前馈

把控制的接口从"关节角"上升到"腿端坐标"，这一步是给 VMC / 全身控制留路：

- 定义腿端量：矢状面 `(x, z)`（轮心相对髋轴）或 `(L, α)`；共模/差模都在这个坐标下写
- 雅可比：离线工具里的中心差分 COM 雅可比 + 解析 Roll 雅可比做法可以搬进运行时（`project/node/chassis/` 新类），或者按腿高工作点把 J 预存进增益文件，跟 K/X0/U0 一起调度（更省，但要求 J 随腿高变化足够平滑）
- 前馈：`τ = JᵀF`，F 里包含支撑力（阶段 C）和水平方向的分量

**验收**：同一组台阶/斜坡下，用 JᵀF 前馈后腿的跟踪误差比纯反馈小；J 的数值与离线工具对同一腿高的输出一致（这条要单独对一次，别只信运行时）。

### 阶段 E：统一 LQR 的评估（只出结论，不动代码）

到这一步再回答"要不要把 Pitch 8 状态 + Roll 4 状态合成 14×6、甚至 16×6"。评估时要带着这三个现有结论去算，不要从零假设：

- 消融预测：`pitch_max_eigenvalue_without` 三个共模全 > 1（1.0178 / 1.0000 / 1.0099）、`roll max_eigenvalue_without` 两个差模也全 > 1（1.1167 / 1.0096）——即任何一路都不能关，统一状态空间不会更宽松
- 一次实测结论：膝的执行器上限 1.5 N·m 是硬约束（`leg.xacro` 的 `leg_effort`），增益过大时环路会在限幅上跑出 5~7° 的腿差极限环；高位（0.09~0.10 m）比低位更容易进去
- φ 与腿差代数相关，进状态要处理不可观/零特征值

## 5. 每阶段都会碰到的两件事

**符号**。φ 的符号、`roll_per_q` 的符号、`leg_joint_sign` 的符号三处必须一致。`chassis.yaml` 里 `leg_joint_sign` 那条注释写着"等 §8 阶段 0 把六个关节正方向确认完再定"，到现在还是四个 1.0。阶段 A 的标定实验顺手把这个确认掉。

**限幅**。腿的执行器上限是 1.5 N·m（模型硬限位），腿差控制在越靠上的高度越吃力（高位下 `Pitch 膝共模`的增益本来就是负的：0.95 → −0.49 → −1.10，设计上高位不靠共模膝）。腿差目标要按腿高设上限，别在山顶高度要一个大腿差。
