# 腿高抖动问题的定位与修复

记录 2026-09-28 处理"站起来/调腿高时两条腿抖"的完整过程：怎么测的、排除了什么、根因是什么、改了什么、改成什么样。数字都是录包实测的，不是估的。

## 1. 现象

- 只在**改腿高时**出现，改完静止时不抖（静止段膝差模角速度 RMS = 0.0000）
- 抖的是**腿**，不是机身：膝差模角摆到 5~7°，而同一时间的 pitch 稳在 1.0~2.5°
- 膝的执行器指令**打到硬限位**：峰值正好 1.500 N·m（= `robot/models/modules/leg.xacro` 里 `leg_effort`），且每拍变化经常贴着 500 N·m/s（`leg_effort_rate_limit`）
- 改之前膝差模角速度峰值**正好卡在 6.00 rad/s**，那是 `leg.xacro` 里 `leg_velocity = 6.0` 的关节速度上限——腿在同时撞力矩限和速度限

## 2. 测量方法（可复现）

抖是 1 kHz 的控制环里几赫兹到上百赫兹的振荡，节点日志是 1 s 一条（`RCLCPP_INFO_THROTTLE`），拿日志看只会看到混叠的正负乱翻。**必须录包**：

```bash
ros2 bag record -o /tmp/shake /joint_states /imu \
    /motor/left/command /motor/right/command \
    /motor/left_hip/command /motor/right_hip/command \
    /motor/left_knee/command /motor/right_knee/command
# 同时改腿高把抖激起来：
ros2 param set /chassis target_height_m 0.080
```

四个指标（后两个是判"饱和"的直接证据）：

| 指标 | 怎么算 |
|---|---|
| 膝差模角 / 角速度 | `½(q_L − q_R)`，位置和速度各一路 |
| 抖窗口 | 膝差模角速度 100 ms 滑窗 RMS 超过静止段 10 倍 |
| 膝指令 \|c\|>1.0 占比 | 实际发出去的力矩里有多少贴在上限附近 |
| 每拍变化 \|Δc\|>0.49 占比 | 0.5 N·m 就是 500 N·m/s × 1 ms，即变化率上限 |

## 3. 改之前的数据

同一组台阶（0.072 → 0.078 → 0.084，`height_rate_mps` 0.01）：

| 指标 | 低位 0.072→0.084 | 高位 0.084→0.102 |
|---|---|---|
| 膝差模角 峰值 | 0.1293 rad（**7.41°**） | 0.0937 rad（5.37°） |
| 膝差模角速度 RMS | 1.404 | 1.597 |
| 膝指令 峰值 | **1.500**（削平） | **1.500**（削平） |
| \|c\|>1.0 占比 | 12.3% | 15.8% |
| \|Δc\|>0.49 占比 | 37.9% | 44.4% |
| 抖的持续段 | 4.8 s → 录完，不衰减 | 整段 17.6 s |

高位还测出**双稳**：同一条台阶跑两次，一次整段抖，一次几乎不抖（只在 5.24 s 有一记 6.3° 的瞬态摆然后收回）。说明它坐在边缘上：平稳推上去没事，被踢一脚就锁进环。

## 4. 排除掉的解释

| 候选解释 | 排除依据 |
|---|---|
| 反馈信号有噪声 | 静止段膝差模角速度 RMS = 0.0000，`角速预测/残差` 全 0；有噪声就不会是这个数 |
| 关节轴约定反了 | 展开 URDF 后六个关节 `<axis>` 全是 `(0 1 0)`；离线工具也校验轴（`generate_wheel_leg_lqr.cpp` 里对 `axis_x/axis_z` 的检查） |
| 踩到软限位 | 高位实测髋共模最大 +0.3835 rad（软限位上界 +0.5109）、膝共模最小 −0.8472（下界 −1.0345），余量 0.127 / 0.187 rad |
| 改高斜坡太快 | `height_rate_mps` 0.01 → 0.003 复测，膝指令 RMS 反而 0.626 → 0.876、\|c\|>1.0 从 12% → 29%。慢速斜坡让腿动得久，抖的时间更长 |
| 设计本身欠阻尼 | 用增益文件里的 `ad/bd/k` 直接算闭环极点：Pitch 全实轴（\|λ\|max 0.9985），Roll 全实轴（0.9968 / 0.9964 / 0.5042 / 0.0001），**一个振荡模态都没有**。所以振源不在"缺阻尼"，在设计模型里没有的东西 |
| 差模环符号反了 | 机器人在差模方向是稳的（滚转 ≈ 0、站得住 30 s 以上），环整体在阻尼。`指令-角速度`相关 +0.204 / 相位 +73°（共模是 −0.193 / +105°）看着可疑，但被角度项污染，不能定性 |

**消融开关不能用来做这个定位。** 五路开关关掉任何一路，闭环都发散（离线算好的 `ablation_prediction`）：

```text
pitch: wheel_common 1.0178 | hip_common 1.0000 | knee_common 1.0099
roll:  hip_diff     1.1167 | knee_diff  1.0096
```

膝共模那一路 1.0099，每拍放大 0.99%，0.5 s 放大 138 倍——关掉就是"直接倒地"。它们只能用来复现"少了某一路会怎样"，不是诊断工具。

## 5. 根因

**腿的环贴着执行器能力在跑**：膝的力矩上限是 1.5 N·m（模型硬限位，改了没用——gz 认的是 URDF 的 `<limit effort>`），变化率上限 500 N·m/s。腿高变化把环推进饱和，饱和限住振幅，形成**极限环**。

三个支撑数字：

1. Roll 膝差模的角增益 31.24 N·m/rad，线性区只有 `1.5 / 31.24 = ±0.048 rad`（±2.7°）——实测腿差已经到 7.4°，早就超了 3 倍
2. 速率增益 8.27 N·m/(rad/s)，实测膝差模角速度 5~6 rad/s，这一项单独就能要 40+ N·m，是上限的 27 倍
3. 分配器告警在改高期间**每 500 ms 一条**：`共模优先裁剪=1`、`变化率=1(scale 0.19~0.73)`——控制器要的力矩远超执行器能给的

所以不是"缺阻尼"，是**执行器跟不上，控制量被削成了贴着限幅的方波/三角波**。加模型阻尼（`leg_damping` 现在是 0.05 N·m·s/rad）或抬力矩上限都不对症：抬上限只会把极限环的振幅按比例放大。

## 6. 改了什么

只改 Q/R 权重（`project/params/chassis.yaml`），然后**用离线工具重新生成全部增益**——运行时节点读的是 `params/leg_gain/*.yaml`，不读 Q/R：

```yaml
r_pitch: [1.0, 2.0, 8.0]    # 第 3 项 tau_k+：2.0 → 8.0
r_roll:  [2.0, 20.0]        # 第 2 项 tau_k-：2.0 → 20.0
```

```bash
ros2 run project generate_wheel_leg_lqr \
    project/robot/models/bodys/wheel_leg_robot.xacro \
    project/params/leg_gain/<name>.yaml project/params/chassis.yaml <腿高>
# 腿高：0.058 / 0.0719922123(nominal) / 0.080 / 0.090 / 0.100 / 0.104
```

六份各自 21 项检查全 PASS、退出码 0。高位那三份（090/100/104）另外用 `r_roll = [2, 60]` 生成——每份增益文件里记着自己生成时的 Q/R（`weights` 段），来路不会丢。

增益变化（Roll 膝差模 角/速，N·m/rad 与 N·m·s/rad）：

| 高度 | 原始 | 第一轮 r=20 | 第二轮（高位 r=60） |
|---|---|---|---|
| 0.058 | 32.56 / 8.62 | 14.58 / 3.60 | — |
| nominal | 31.24 / 8.27 | 13.64 / 3.34 | — |
| 0.080 | 29.31 / 7.78 | 12.71 / 3.11 | — |
| 0.090 | 25.42 / 6.80 | 11.04 / 2.73 | **7.36 / 1.68** |
| 0.100 | 19.12 / 5.20 | 8.59 / 2.17 | **5.72 / 1.34** |
| 0.104 | 15.39 / 4.24 | 7.25 / 1.87 | **4.85 / 1.17** |

闭环最大极点没退化（roll 0.9968、pitch 0.9985，与改之前相同）。

`install/project/share/project/params/` 是软链到源码的，所以改完**不用 colcon build**，重启仿真即可（增益在节点构造时加载）。

| 高位 0.090→0.102（第 1 次） | 5.37°，RMS 1.597，峰值 1.500，15.8%，44.4% | **0.01°**，RMS **0.001**，峰值 0.675，**0.0%**，0.1% |

高位原来那条"两次跑出两种结果"的双稳消失，两次都干净。

## 8. 遗留问题

**静止时腿高有 4.1~4.2 mm 稳态误差**（目标 0.102，实测 0.0979；低位目标 0.0868、实测 0.0826，连续几秒纹丝不动）。成因是状态反馈**没有积分作用**：模型质量数（`leg_rod_mass` / `leg_joint_mass` / `wheel_mass`）跟 URDF 对不上时，只能靠一个固定的腿角偏差顶住。跟抖无关，是独立的一轮。

## 9. 走过弯路（记下来免得再走）

1. **第一次读日志读出了错结论**。从用户的 1 s 节流日志看，膝差模指令到过 ±18 N·m、分配器告警连刷 30 s，我判断是"持续 12 倍饱和"。实测（录包）后发现那是瞬时峰值 + 混叠：爆发段里 `|c|>1.0` 只占 1%。**结论：这类判断必须录包，不能拿节流日志推。**
2. **拿消融开关做定位，把机器人弄倒了**。`enable_knee_common=false` 之后直接倒地——那五路都是稳定必需的（见 §4）。想单独关一路看抖还在不在，这条路根本走不通。
