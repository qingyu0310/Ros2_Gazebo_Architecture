# 轮腿机器人全身平衡 LQR 实施规划

> 目标：在当前 `framework / gazebo / ros2_layer / project` 四层架构上，将现有“仅由左右轮维持 Pitch 的 4 状态、1 输入 LQR”，逐步升级为轮、髋、膝共同参与的轮腿机器人全身平衡控制。
>
> 本文是实施规划，不直接修改控制代码。规划优先采用“左右共模/差模分解 + 固定工作点 LQR + 增益调度”的路线，不建议第一步就把控制器直接替换成未经验证的 `14 × 6` 大模型。

---

## 1. 当前工程结论

### 1.1 已经具备的基础

当前工程并不是从零开始，以下基础已经存在：

| 能力 | 当前文件 | 现状 |
|---|---|---|
| 通用离散 LQR 求解器 | `framework/algorithm/controller/lqr.hpp` | 已实现 DARE 迭代、`K` 求解和 `u = -K(x - x_ref)` |
| 通用 KF / EKF | `framework/algorithm/filter/kalman/` | 已有基础模板，可以继续复用 |
| IMU 姿态解算 | `framework/modules/sensors/imu.hpp` | 已有四元数姿态解算模块 |
| 单关节电机模块 | `framework/modules/motors/motor.hpp` | 已支持力矩直通、限幅、超时保护和速度模式 |
| ROS 2 电机适配 | `ros2_layer/node/motor/motor.hpp` | 一个 `MotorNode` 对应一个关节，可复用为六个实例 |
| Gazebo 力矩执行器 | `gazebo/plugins/motor/torque_motor.xacro` | 使用 `ApplyJointForce`，适合 LQR 直接输出关节力矩 |
| IMU 与关节反馈 | `imu.xacro`、`joint_encoder.xacro` | 可以输出 `/imu` 与 `/joint_states` |
| 两轮倒立摆控制器 | `project/node/chassis/chassis.hpp` | 已能构造 4 状态、1 输入的 A/B/Q/R 并求解 LQR |

当前分层方向是正确的：

- `framework` 保持 ROS 2 无关，放通用算法和通用模块；
- `gazebo` 放仿真图元、传感器和执行器插件；
- `ros2_layer` 只做 ROS 消息与通用模块之间的适配；
- `project` 放这台轮腿机器人的状态定义、动力学、控制策略、参数与启动装配。

### 1.2 模型已经发生的变化

当前源码中的左右髋关节和左右膝关节已经从固定关节改为可动力矩控制的 `revolute` 关节：

- `left_hip_joint`
- `right_hip_joint`
- `left_knee_joint`
- `right_knee_joint`
- `left_wheel_joint`
- `right_wheel_joint`

当前模型展开后能够通过 `xacro` 和 `check_urdf`，六个运动关节均存在，髋/膝力矩入口也已经生成。

髋关节硬限位为：

```text
q_h ∈ [-15°, 35°]
```

膝关节硬限位为：

```text
q_k ∈ [-65°, 25°]
```

按当前对称伸缩关系

```text
q_k = -2 * q_h
```

联立两组关节限位后，实际可用的对称髋关节范围约为：

```text
q_h ∈ [-12.5°, 32.5°]
```

控制工作点必须位于该范围内部，并额外预留软限位，不能让 LQR 把硬限位当作正常控制边界。

### 1.3 当前控制链与模型不再匹配

目前存在的主要差距如下：

1. `ChassisNode` 仍然使用 `Lqr<4, 1>`，状态只有轮子位移、轮子速度、Pitch、Pitch 角速度，控制输入只有左右轮公共力矩。
2. `sim.launch.py` 只桥接左右轮的两个 `cmd_force`，尚未桥接四个腿关节力矩话题。
3. `ChassisNode` 只创建两个轮电机 `MotorNode`，尚未创建左右髋、左右膝电机实例。
4. `/joint_states` 虽然可以包含六个运动关节，但现有状态提取逻辑只读取左右轮。
5. 当前 A/B 是固定腿刚体倒立摆模型。腿变成活动关节后，原有 `body_mass / body_com_height / body_pitch_inertia` 降阶模型不再成立。
6. 当前教程仍有“腿是 fixed”的旧描述，需要在全身控制完成后同步修订，避免两套控制假设互相冲突。
7. 轮子模型默认半径目前是 `0.030 m`，但 `chassis.yaml`、`SPAWN_Z` 和旧教程仍按 `0.040 m` 计算。这个物理参数必须先统一，否则 A/B、里程换算、离地高度和附着力矩都会同时出错。

因此，下一步不能只把模板参数改成 `Lqr<14, 6>`。必须先补齐真实动力学、六执行器链路、完整状态估计和安全约束。

## 2. 控制目标与边界

### 2.1 第一阶段需要实现的目标

全身平衡控制第一版应完成：

1. 平地静止时保持机身 Pitch 和 Roll 接近零；
2. 左右轮、左右髋、左右膝均能参与控制；
3. 髋膝维持指定标准腿姿或指定腿高；
4. 接受前进速度和偏航角速度目标；
5. 任一反馈缺失、超时、姿态倒地或关节接近硬限位时进入安全状态；
6. 输出力矩严格满足各关节力矩上限和轮地附着约束；
7. 能记录每一维状态、目标、原始 LQR 输出、限幅后输出和工作点编号。

### 2.2 第一版暂不追求的能力

以下能力不应和第一版全身平衡同时开发：

- 跳跃和落地控制；
- 腾空状态控制；
- 台阶、坡地和复杂接触切换；
- 在线求解非线性最优控制；
- 自动辨识全部真实电机参数；
- 在任意腿姿下只用一套固定 K；
- 用 LQR 直接处理硬碰撞和硬限位。

这些功能应建立在固定工作点和增益调度已经稳定之后。

## 3. 状态、输入与工作点定义

### 3.1 完整物理状态

与当前六个执行器对应的基础状态定义为：

```text
X = [
    s, s_dot,
    pitch, pitch_rate,
    roll, roll_rate,
    q_hL, q_hL_dot,
    q_kL, q_kL_dot,
    q_hR, q_hR_dot,
    q_kR, q_kR_dot
]^T
```

其中：

| 状态 | 含义 | 单位 | 主要来源 |
|---|---|---:|---|
| `s` | 沿前进方向的等效位移 | m | 轮编码器与腿部运动学融合 |
| `s_dot` | 沿前进方向的速度 | m/s | 轮速与状态估计器 |
| `theta` | 机身 Pitch | rad | IMU |
| `theta_dot` | Pitch 角速度 | rad/s | IMU 陀螺仪 |
| `phi` | 机身 Roll | rad | IMU |
| `phi_dot` | Roll 角速度 | rad/s | IMU 陀螺仪 |
| `q_hL/q_hR` | 左右髋角 | rad | `/joint_states` |
| `q_kL/q_kR` | 左右膝角 | rad | `/joint_states` |
| 各关节角速度 | 对应关节速度 | rad/s | `/joint_states` |

控制输入为六个关节力矩：

```text
U = [tau_wL, tau_wR, tau_hL, tau_hR, tau_kL, tau_kR]^T
```

需要特别注意：轮角平均值只能在“轮子纯滚动、腿姿不改变机身与轮轴相对位置”的简化条件下直接等价为机身位移。腿开始运动后，状态估计器必须考虑腿部运动学；仿真阶段还应增加模型世界位姿或里程反馈作为对照真值。

### 3.2 控制器实际使用的是偏差量

真正的控制律不应直接写成：

```text
U = -K * X
```

而应围绕工作点写成：

```text
delta_X = X - X0
U = U0 - K * delta_X
```

其中：

- `X0` 是目标腿姿、目标机身姿态和目标运动状态；
- `U0` 是该腿姿下抵消重力所需的髋/膝前馈力矩；
- `-K * delta_X` 只负责抑制工作点附近的扰动。

如果省略 `U0`，LQR 必须长期输出一个固定偏差来抵消腿部重力，工作点会偏移，积分外环和限幅也更容易互相影响。

### 3.3 左右共模/差模坐标

优先使用左右对称性降低调试复杂度。

髋关节定义：

```text
q_h_common = (q_hL + q_hR) / 2
q_h_diff   = (q_hL - q_hR) / 2
```

膝关节定义：

```text
q_k_common = (q_kL + q_kR) / 2
q_k_diff   = (q_kL - q_kR) / 2
```

力矩同样分解：

```text
tau_a_common = (tau_aL + tau_aR) / 2
tau_a_diff   = (tau_aL - tau_aR) / 2
```

其中 `a` 可以是轮、髋或膝。

推荐的 Pitch 子系统为：

```text
X_pitch = [
    s, s_dot,
    pitch, pitch_rate,
    q_h_common, q_h_common_rate,
    q_k_common, q_k_common_rate
]^T

U_pitch = [tau_w_common, tau_h_common, tau_k_common]^T
```

推荐的 Roll 子系统初始定义为：

```text
X_roll = [
    roll, roll_rate,
    q_h_diff, q_h_diff_rate,
    q_k_diff, q_k_diff_rate
]^T
```

Roll 子系统先使用：

```text
U_roll = [tau_h_diff, tau_k_diff]^T
```

轮子差动力矩 `tau_w-` 不应未经验证就当成 Roll 执行器。它在当前结构中的主要作用是偏航，是否能在线性工作点附近有效控制 Roll，必须由 B 矩阵和可控性检验决定。

如果后续要把偏航也纳入同一个最优控制问题，应增加 `yaw/yaw_rate` 状态，形成差模的 Roll + Yaw 联合子系统；否则保留当前偏航角速度外环，把 `tau_w-` 单独分配给转向。

### 3.4 从共模/差模恢复六路物理力矩

```text
tau_wL = tau_w_common + tau_w_diff
tau_wR = tau_w_common - tau_w_diff
tau_hL = tau_h_common + tau_h_diff
tau_hR = tau_h_common - tau_h_diff
tau_kL = tau_k_common + tau_k_diff
tau_kR = tau_k_common - tau_k_diff
```

力矩恢复后还必须经过统一分配器处理软限位、硬限幅、力矩变化率和轮地附着约束，不能让六个电机节点各自独立裁剪后破坏左右共模/差模比例。

## 4. 动力学模型与 A/B 获取路线

### 4.1 非线性模型必须包含接触约束

轮腿机器人不是悬空机械臂。基础方程应写为：

```text
M(q) * q_ddot + C(q, q_dot) * q_dot + G(q)
    = S^T * tau + Jc^T * lambda
```

同时满足轮地接触和滚动约束：

```text
Jc * q_ddot + Jc_dot * q_dot = 0
```

其中：

- `M(q)` 是质量矩阵；
- `C(q,q_dot)q_dot` 是科氏力和离心力；
- `G(q)` 是重力项；
- `S` 描述六个执行器作用在哪些广义坐标上；
- `Jc` 是接触约束雅可比；
- `lambda` 是地面对轮子的约束力。

如果只从 URDF 得到悬空刚体动力学而不处理轮地约束，得到的 A/B 不能直接用于站立平衡。

### 4.2 工作点求解

每个工作点至少包含：

```text
X0 = [目标速度、Pitch=0、Roll=0、左右髋膝目标角及全部目标角速度]
U0 = [轮力矩前馈、左右髋重力补偿、左右膝重力补偿]
```

静止站立工作点应满足：

```text
f(X0, U0) = 0
```

工作点求解需要检查：

1. 两个轮子都保持接触；
2. 法向力为正；
3. 髋膝角不接近硬限位；
4. 重力补偿力矩不超过 `1.5 N·m`；
5. 摩擦需求位于摩擦锥内；
6. 左右对称工作点的横向质心位于支撑区域内。

### 4.3 线性化

在每个工作点计算：

```text
Ac = df/dX evaluated at (X0, U0)
Bc = df/dU evaluated at (X0, U0)
```

然后用控制周期离散化：

```text
Ad = exp(Ac * dt)
Bd = integral(exp(Ac * t) * Bc, t = 0 ... dt)
```

现有 1 ms 控制周期下，前向欧拉可用于最初对照，但全身模型建议使用零阶保持离散化，并比较两种方法的闭环特征值。

### 4.4 A/B 的生成方式

建议将 A/B 生成做成离线工具，而不是把复杂多刚体公式直接堆进 ROS 回调：

1. 从展开后的 URDF 读取质量、惯量、关节轴和几何关系；
2. 建立带双轮接触约束的非线性状态方程；
3. 求解 `X0/U0`；
4. 用解析雅可比、自动微分或经过误差验证的中心差分计算 A/B；
5. 做可控性、稳定性和维度检查；
6. 根据 Q/R 求解 K；
7. 输出带模型摘要和工作点信息的增益文件；
8. 运行时加载增益，并校验状态顺序、输入顺序、控制周期和模型版本。

禁止在 YAML 中手工填写一组没有生成依据的 A/B，或把手调反馈系数命名为 LQR 增益。

### 4.5 必须执行的数学检查

每个工作点都应自动检查：

| 检查项 | 判据 |
|---|---|
| 矩阵维度 | 与状态和输入枚举完全一致 |
| 有限性 | A/B/Q/R/K 不含 NaN 或 Inf |
| Q | 对称半正定 |
| R | 对称正定 |
| 可控性 | `rank([B, AB, ..., A^(n-1)B])` 满足设计要求 |
| 开环特征值 | 能识别倒立不稳定模态 |
| 闭环特征值 | 离散系统 `A-BK` 的目标模态位于单位圆内 |
| 左右对称性 | 左右交换后共模/差模结构不应无故变化 |
| 数值线性化 | 扰动幅值改变一个数量级时 A/B 不应剧烈漂移 |

若 Roll 子系统不可控，不应靠继续增大 Q 掩盖问题，应先检查机械自由度、接触模型和输入选择。

## 5. 建议的代码落点

### 5.1 `framework`：只保留通用数学能力

建议保留并补强：

```text
framework/
├── algorithm/
│   ├── controller/
│   │   └── lqr.hpp                         # 现有 DARE 求解器
│   └── model/
│       ├── state_space.hpp                 # 通用状态空间数据结构
│       ├── discretization.hpp              # ZOH/欧拉离散化
│       └── numerical_linearizer.hpp        # 通用数值雅可比，可选
└── modules/
    └── motors/
        └── motor.hpp                       # 现有单电机限幅/超时
```

`framework` 不应出现 `left_hip_joint`、轮距、腿长或本机器人专用的 14 维状态顺序。

### 5.2 `gazebo`：继续只提供通用仿真能力

```text
gazebo/
├── plugins/motor/torque_motor.xacro
├── plugins/sensor/imu.xacro
└── plugins/sensor/joint_encoder.xacro
```

这一层已有的力矩入口和反馈插件可以直接复用。六个具体关节如何桥接仍由 `project/launch` 决定。

### 5.3 `ros2_layer`：保持单关节适配器通用

现有 `MotorNode` 已经满足“一实例一关节”的结构，不需要为髋、膝各复制一种节点类。需要补的是：

- 支持六实例的统一构造配置；
- 明确命令超时和反馈超时；
- 输出电机是否 active、是否限幅等诊断状态；
- 运行时不要让各电机自行采用互相矛盾的力矩限制。

### 5.4 `project`：放机器人专用控制

建议按以下结构拆开当前过于集中的 `chassis.hpp`：

```text
project/
├── control/wheel_leg/
│   ├── state.hpp                           # 状态、输入及枚举，固定顺序
│   ├── coordinate_transform.hpp            # 左右量和共模/差模互换
│   ├── state_estimator.hpp                 # IMU、编码器和运动学融合
│   ├── dynamics.hpp                        # 本机器人非线性动力学接口
│   ├── operating_point.hpp                 # X0/U0 与工作点元数据
│   ├── whole_body_controller.hpp           # Pitch/Roll LQR 与前馈合成
│   ├── gain_scheduler.hpp                  # 按腿姿插值 K 和 U0
│   ├── torque_allocator.hpp                # 六路恢复、限幅、软限位
│   └── safety_supervisor.hpp                # 倒地、超时、越界保护
├── node/chassis/
│   ├── chassis.hpp                         # 只保留 ROS 收发、参数和调度
│   └── chassis.cpp                         # main 与 executor
├── params/
│   ├── chassis.yaml                        # 话题、频率、遥控和安全参数
│   └── whole_body_lqr.yaml                 # Q/R、工作点和调度参数
├── gains/wheel_leg/
│   ├── nominal.yaml                        # 标准腿姿的 X0/U0/A/B/K 摘要
│   └── ...                                 # 其他腿姿工作点
└── tools/
    └── generate_wheel_leg_lqr.cpp          # 离线建模、线性化、求 K
```

这里的 `control/wheel_leg` 虽然不直接依赖 ROS 消息，但它属于当前机器人，不应为了“看起来通用”而塞入 `framework`。

## 6. 运行时数据流

```text
Gazebo / 实机
  ├─ IMU ----------------------------------------------------┐
  ├─ 六关节 position / velocity ----------------------------┤
  └─ 仿真世界位姿或里程真值（仅验证） ----------------------┤
                                                            ▼
                                                StateEstimator
                                                            │ X
                                                            ▼
                                               坐标变换与目标生成
                                                ├─ X_pitch
                                                └─ X_roll
                                                            │
                           ┌────────────────────────────────┴──────────────┐
                           ▼                                               ▼
                    Pitch LQR 8×3                                  Roll LQR 6×2
        tau_w_common / tau_h_common / tau_k_common       tau_h_diff / tau_k_diff
                           └──────────────────────┬────────────────────────┘
                                                  ▼
                         偏航外环产生 tau_w_diff + 六路力矩恢复
                                                  ▼
                                      TorqueAllocator / Safety
                                                  ▼
                         六个 MotorNode：轮×2、髋×2、膝×2
                                                  ▼
                                   六路 Gazebo cmd_force
```

当分块模型全部验证后，再决定是否切换成统一 `Lqr<14,6>`。统一大模型应是对已经验证的分块模型的升级，不是第一块调试代码。

## 7. 参数设计

### 7.1 Pitch 子系统 Q

Pitch 状态顺序固定为：

```text
[s, s_dot, pitch, pitch_rate, hip_common, hip_common_rate, knee_common, knee_common_rate]
```

对应：

```text
Q_pitch = diag(
    q_s, q_s_dot,
    q_pitch, q_pitch_rate,
    q_h_common, q_h_common_rate,
    q_k_common, q_k_common_rate
)
```

初始优先级建议为：

```text
Pitch / Pitch rate > 髋膝姿态 > 速度 > 位置
```

第一轮参数只定义量级和调参方向，不把未经仿真验证的数值写成最终值。

### 7.2 Roll 子系统 Q

Roll 状态顺序固定为：

```text
[roll, roll_rate, hip_diff, hip_diff_rate, knee_diff, knee_diff_rate]
```

对应：

```text
Q_roll = diag(
    q_roll, q_roll_rate,
    q_h_diff, q_h_diff_rate,
    q_k_diff, q_k_diff_rate
)
```

Roll 权重不能只看角度误差，还要限制左右腿差动幅度，避免为了机身水平把一侧腿推到限位。

### 7.3 R 决定执行器分工

Pitch 输入权重：

```text
R_pitch = diag(r_w_common, r_h_common, r_k_common)
```

Roll 输入权重：

```text
R_roll = diag(r_h_diff, r_k_diff)
```

调参含义：

- 减小 `r_w+`：更愿意用轮子救 Pitch，但位置漂移和轮胎打滑风险增加；
- 减小 `r_h+`：更愿意用髋部反作用和平衡；
- 减小 `r_k+`：更愿意改变腿构型，但腿高波动增大；
- 减小差模髋膝 R：Roll 调平更积极，但左右腿动作和关节载荷增大。

不能只根据“希望哪个电机多动”调整 R，还要结合力矩上限、带宽、关节速度和可控性。所有 Q/R 参数都应在 YAML 中写清状态顺序、单位、增大/减小的效果。

## 8. 分阶段实施计划

### 阶段 0：冻结并校准物理模型

#### 工作内容

1. 统一轮子半径、宽度、spawn 高度、控制参数和教程中的数值；
2. 确认六个关节的正方向；
3. 确认髋膝零位与标准腿姿一致；
4. 为髋膝设置软限位，硬限位只作为最后保护；
5. 从展开 URDF 自动汇总每个 link 的质量、质心和惯量；
6. 检查左右模型严格对称；
7. 保存当前两轮控制基线，避免后续无法区分模型问题和控制问题。

#### 验收标准

- `xacro` 与 `check_urdf` 通过；
- 六个运动关节名称、轴向、限位和力矩入口正确；
- 标准腿姿下两轮同时接地；
- YAML、xacro、launch 中不存在 0.03/0.04 m 的轮径冲突；
- 单独给每个关节很小的正力矩时，实际运动方向有记录。

### 阶段 1：打通六执行器链路

#### 工作内容

1. `sim.launch.py` 增加四个髋膝力矩桥；
2. 将电机配置从固定两个轮子扩展为六执行器表；
3. 复用 `MotorNode` 创建六个实例；
4. `/joint_states` 一次性解析六个运动关节；
5. 增加关节反馈超时和命令超时；
6. 增加六路力矩、角度、角速度诊断输出。

#### 验收标准

- 六个 ROS 力矩命令都能到达对应 Gazebo 关节；
- 六个关节反馈名称、位置、速度均持续更新；
- 任意单关节测试不会误驱动其他关节；
- 命令停止后所有执行器在规定时间内回零力矩。

### 阶段 2：先做腿姿保持，不接入全身 LQR

#### 工作内容

1. 计算标准腿姿的髋膝重力补偿 `U0`；
2. 使用独立、明确命名的关节姿态保持器验证零位、符号和限幅；
3. 保留现有轮式 Pitch LQR 作为临时基线；
4. 验证腿在自重下不会折叠，并能回到标准工作点。

这一阶段的关节保持器只是执行链路验证工具，不应被当成最终“全身 LQR”。

#### 验收标准

- 标准腿姿静止误差受控；
- 无持续撞击硬限位；
- 重力补偿方向正确；
- 四个腿关节力矩和温和扰动后的恢复过程可记录。

### 阶段 3：建立固定腿姿的 Pitch 8 状态、3 输入 LQR

#### 工作内容

1. 建立 Pitch 非线性模型；
2. 求标准腿姿下的 `X0/U0`；
3. 生成 `A_pitch/B_pitch`；
4. 检查可控性和开闭环特征值；
5. 求解 `K_pitch`；
6. 用 `tau_w+ / tau_h+ / tau_k+` 替换旧的单轮公共力矩控制；
7. 保留轮差动力矩偏航外环，但先将移动目标设为零完成站立验证。

#### 验收标准

- 静止时 Pitch 有界且能回到零附近；
- 三种共模执行器均有合理输出，而不是某一路永久饱和；
- 小扰动后能够收敛；
- 轮位移、关节角和力矩均不持续发散；
- 禁用任一类执行器后，性能变化与 B 矩阵预测一致。

### 阶段 4：建立 Roll 6 状态、2 输入 LQR

#### 工作内容

1. 建立差模腿运动与机身 Roll 的动力学；
2. 生成 `A_roll/B_roll`；
3. 先验证髋差模、膝差模对 Roll 的控制效果；
4. 检查轮差动力矩对 Roll 的实际线性控制能力；
5. 若轮差主要产生 Yaw，则继续把它留给偏航外环；
6. 合成 Pitch 和 Roll 的共模/差模力矩。

#### 验收标准

- Roll 子系统可控；
- 左右腿差动方向正确；
- Roll 扰动后能恢复，同时 Pitch 不出现明显失稳；
- 左右关节均不进入软限位保护区；
- 力矩合成前后满足对称性测试。

### 阶段 5：六路力矩统一分配与安全监督

#### 工作内容

1. 在一个 `TorqueAllocator` 中完成共模/差模恢复；
2. 对轮、髋、膝分别设置力矩上限和力矩变化率；
3. 采用成组缩放，尽量保留左右力矩比例；
4. 加入髋膝软限位恢复力矩；
5. 同时检查 Pitch、Roll、反馈时间戳和关节越界；
6. 倒地后清零动态目标，重新扶正时重新标定位移原点和状态估计器。

#### 验收标准

- 任意组合控制下均无关节命令越限；
- 限幅发生时有明确诊断；
- 单一传感器停止更新时，系统进入可预测的安全状态；
- 安全逻辑不在正常状态下反复抢占 LQR。

### 阶段 6：加入运动目标

#### 工作内容

1. 恢复前进速度目标；
2. 重新设计位置目标积分和防漂移策略；
3. 保留或升级偏航角速度外环；
4. 检查速度目标变化时腿姿目标是否需要前馈调整；
5. 验证 Pitch/Roll 平衡优先级高于轨迹跟踪。

#### 验收标准

- 前进、后退、停车过程中不失稳；
- 指令超时后平稳回到零速度目标；
- 转向时 Pitch/Roll 不出现持续偏差；
- 轮地打滑时能在日志中被识别，而不是误判为 LQR 参数错误。

### 阶段 7：增益调度

#### 工作内容

1. 选择若干安全腿姿工作点；
2. 每个工作点独立求解 `X0/U0/A/B/K`；
3. 按 `q_h+ / q_k+` 或等效腿高选择相邻工作点；
4. 对 K 和 U0 做连续插值；
5. 对调度速度加限制，避免 K 突变；
6. 验证整个调度区域的闭环稳定性和力矩裕量。

#### 验收标准

- 从最低工作点到最高工作点连续变化时无力矩跳变；
- 每个工作点附近均能恢复 Pitch/Roll；
- 插值区域内闭环特征值和仿真响应无异常突变；
- 超出调度区域时拒绝继续伸缩，而不是外推 K。

### 阶段 8：再评估统一 14×6 或 16×6 LQR

只有分块控制已经通过验收，才比较：

- `8×3 Pitch + 6×2 Roll + Yaw 外环`；
- `14×6` 全状态 LQR；
- 加入 Yaw/Yaw rate 后的 `16×6` 全状态 LQR。

比较指标包括控制效果、可解释性、数值条件、工作点调度复杂度、饱和恢复和实机迁移难度。若统一大模型没有明确收益，应保留分块方案。

## 9. 状态估计规划

### 9.1 仿真阶段

仿真第一版可以使用：

- `/imu.orientation` 提供 Pitch/Roll 真值；
- `/imu.angular_velocity` 提供角速度；
- `/joint_states` 提供六个关节角和角速度；
- Gazebo 世界位姿或里程作为 `s/s_dot` 的验证真值。

控制器不能永久依赖 Gazebo 真值。仿真真值主要用于验证轮编码器、腿部运动学和滤波后的估计误差。

### 9.2 实机迁移前

实机应改为：

- IMU 姿态融合输出；
- 编码器关节状态；
- 轮式里程计；
- 必要时加入机身加速度和腿部正运动学约束；
- 对所有反馈使用统一时间基准和时间戳。

现有控制器使用固定 `dt` 和 wall timer。全身控制前应决定以传感器时间戳驱动，还是使用仿真时间定时器，并记录实际周期抖动。动力学离散化使用的 `dt` 必须与实际控制节拍一致。

## 10. 安全与限幅设计

### 10.1 关节限制

硬限位来自 URDF，软限位建议向内收缩，例如预留若干角度作为缓冲区。软限位区域内逐渐增加恢复力矩，超出安全区后停止正常 LQR 输出并进入保护状态。

### 10.2 力矩限制

当前模型上限为：

- 轮关节：`5.0 N·m` 的 URDF 硬限制；
- 髋关节：`1.5 N·m`；
- 膝关节：`1.5 N·m`。

轮子的真正可用力矩通常先受轮地附着限制，而不是 `5.0 N·m` 电机硬限制。控制器中的轮力矩预算必须根据法向力、摩擦系数和轮径计算。

### 10.3 保护条件

至少包括：

- IMU 超时；
- 关节反馈超时；
- 任一状态为 NaN/Inf；
- Pitch 或 Roll 超过倒地阈值；
- 髋膝进入硬限位危险区；
- 控制周期异常；
- 增益文件与模型状态顺序不一致；
- 连续多拍力矩饱和；
- 接触丢失或法向力异常（后续阶段）。

## 11. 测试与验收矩阵

### 11.1 单元测试

| 对象 | 测试内容 |
|---|---|
| LQR | 已知系统的 K、DARE 收敛、非法 Q/R、闭环特征值 |
| 坐标变换 | 左右量到共模/差模再还原，误差应接近机器精度 |
| 状态顺序 | 枚举、矩阵行列和 YAML 顺序一致 |
| 线性化 | 与中心差分对比，扰动步长敏感性检查 |
| 力矩分配 | 共模、差模、饱和、软限位、NaN 输入 |
| 增益调度 | 工作点边界、插值连续性、越界拒绝 |

### 11.2 接口测试

1. `/joint_states` 包含六个关节；
2. `/imu` 频率、时间戳和坐标系正确；
3. 六个力矩话题类型、方向和单位正确；
4. 六个 `MotorNode` 都能收到命令并发布力矩；
5. source 与 install 空间中的参数、模型和 launch 一致。

### 11.3 仿真验收指标

每次测试至少记录：

- Pitch / Roll 峰值与 RMS；
- Pitch / Roll 收敛时间；
- 前后位置漂移；
- 四个腿关节的最大偏差；
- 六路力矩峰值和饱和占空比；
- 控制周期均值、最大值和抖动；
- 轮胎滑移；
- 工作点编号和当前 K。

建议按以下顺序验收：

1. 标准腿姿静止；
2. 仅 Pitch 小扰动；
3. 仅 Roll 小扰动；
4. Pitch + Roll 组合扰动；
5. 低速前进与停车；
6. 低速转向；
7. 不同固定腿高；
8. 连续腿高调度；
9. 传感器超时和命令超时；
10. 饱和与软限位保护。

在完成连续、干净、单模型、单控制器进程的测试前，不能仅凭 `colcon build` 成功或机器人短时间未倒就认定全身平衡完成。

## 12. 推荐的实际开发顺序

按依赖关系，推荐严格使用以下顺序：

```text
统一模型参数
  → 验证六关节方向与反馈
  → 打通六路力矩桥
  → 腿姿重力补偿与保持
  → Pitch 8×3 固定工作点 LQR
  → Roll 6×2 固定工作点 LQR
  → 六路力矩分配与安全监督
  → 前进/偏航目标
  → 多工作点增益调度
  → 评估统一 14×6 或 16×6 LQR
  → 实机状态估计与电机模型
```

第一轮实现的最小闭环里程碑应定为：

> 在标准腿姿下，左右轮、左右髋、左右膝的执行链全部打通；通过真实 A/B 和 Q/R 分别求得 Pitch 与 Roll LQR；机器人静止时能同时抑制 Pitch 和 Roll，且关节不撞限位、力矩不长期饱和。

完成这个里程碑后，再进入走动、转向和腿高调度，风险最小，也最容易定位问题。

## 13. 开工前必须先确认的五项决定

1. 轮子真实目标半径究竟是 `0.030 m` 还是 `0.040 m`；
2. 第一版是否采用推荐的 `Pitch 8×3 + Roll 6×2 + Yaw 外环`；
3. 多刚体动力学准备采用哪种库或自研方式；
4. 标准腿姿的 `q_h0/q_k0` 和目标机身高度；
5. 第一版只做固定腿姿，还是同时准备多个腿高工作点。

这五项决定中，第 1 项必须在任何 A/B 计算之前完成；第 3 项决定动力学工具的代码结构；第 4、5 项决定工作点和增益文件的数量。
