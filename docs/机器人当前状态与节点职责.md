# 轮腿机器人代码分析

> 本文按当前源码的真实调用链分析代码，不把规划内容当成已实现功能。

## 1. 完整调用链

运行 `ros2 launch project sim.launch.py` 后，代码链路是：

```text
sim.launch.py
├─ Gazebo + wheel_leg_robot.xacro
├─ robot_state_publisher
├─ ros_gz_bridge
├─ ChassisNode
│  ├─ 缓存 /imu
│  ├─ 缓存 /joint_states
│  ├─ 缓存 /chassis/cmd_vel
│  └─ 1 kHz update()
│     ├─ 安全检查
│     ├─ 生成身高参考
│     ├─ PitchLqrController → 轮/髋/膝共模力矩
│     ├─ RollLqrController  → 髋/膝差模力矩
│     ├─ 偏航 P 环 → 轮差模力矩
│     └─ TorqueAllocator → 六路关节力矩
└─ motor 进程
   └─ 六个 MotorNode → 六路 cmd_force → Gazebo
```

键盘不在 launch 中，需要单独运行 `ros2 run project keyboard`。

## 2. `sim.launch.py` 怎么接线

文件：`project/launch/sim.launch.py`

`ACTUATORS` 保存 ROS 执行器名与 URDF 关节名：

```python
('left',       'left_wheel_joint')
('right',      'right_wheel_joint')
('left_hip',   'left_hip_joint')
('right_hip',  'right_hip_joint')
('left_knee',  'left_knee_joint')
('right_knee', 'right_knee_joint')
```

循环为每个执行器生成 ROS → Gazebo 力矩桥。例如：

```text
/motor/left/cmd_force
  → /model/wheel_leg_robot/joint/left_wheel_joint/cmd_force
```

反馈方向还有：

```text
/joint_states  Gazebo → ROS
/imu           Gazebo → ROS
/clock         Gazebo → ROS
```

launch 实际启动 `chassis` 和 `motor`。`imu` 节点被注释。

## 3. `ChassisNode` 保存了什么

文件：`project/node/chassis/chassis.hpp`

### 3.1 参数结构

| 结构体 | 内容 |
|---|---|
| `ModelParams` | 轮半径、质量、质心高度、惯量、阻尼、重力 |
| `ControlParams` | dt、力矩上限、倒地角、方向符号、Roll Q/R |
| `LegParams` | 四个腿关节的名称、话题、限位、力矩和速度限制 |
| `SafetyParams` | 反馈超时、控制周期超时、恢复驻留时间 |
| `HeightParams` | 腿长、标准角、目标高度、变化率、质量 |
| `RemoteParams` | 速度、偏航、身高步长和命令超时 |

### 3.2 反馈状态

`ChassisState` 缓存：

```text
roll, roll_rate, pitch, pitch_rate, yaw_rate
wheel_position, wheel_velocity, position_origin
四个腿关节的位置和速度
```

`TeleopTarget` 保存目标速度、目标偏航角速度，以及由目标速度积分出来的位置参考。

### 3.3 两个运行时 LQR 类

`pitch_lqr.hpp` 和 `roll_lqr.hpp` 已从 `ChassisNode` 中拆出纯控制律：

- `PitchLqrController` 保存 8 状态 3 输入的 K/X0/U0，计算 `U=Uff-K(X-Xref)`；
- `RollLqrController` 保存 4 状态 2 输入的 K/X0/U0 和 `roll_per_q`，计算腿差模力矩与几何预测；
- 两个类都负责工作点线性插值、有限性检查和“未配置禁止运行”；
- 两个类不依赖 ROS 和 YAML；`ChassisNode` 只组装它们需要的状态，文件加载、安全监督和力矩分配由相邻独立模块负责。

### 3.4 `chassis` 目录的职责拆分

`ChassisNode` 不再内嵌参数解析、增益文件解析和安全状态机：

| 文件 | 职责 |
|---|---|
| `chassis_types.hpp` | 参数、反馈、遥控目标等共享数据类型 |
| `chassis_config.hpp` | ROS 参数声明、配置校验、分配器和腿高配置生成 |
| `lqr_gain_schedule.hpp` | YAML 读取、状态/输入顺序、dt、轮半径和模型哈希校验，以及多高度插值 |
| `safety_supervisor.hpp` | 反馈超时、周期异常、倒地、关节越界和恢复驻留状态机 |
| `leg_gravity_compensation.hpp` | 按当前腿姿计算髋膝静态重力前馈 |
| `pitch_lqr.hpp` / `roll_lqr.hpp` | 两套纯 LQR 控制律 |
| `leg_height.hpp` | 对称腿高运动学和参考斜坡 |
| `torque_allocator.hpp` | 共差模恢复、软限位、力矩及变化率约束 |

因此 `chassis.hpp` 只保留 ROS publisher/subscriber、三个回调、动态参数处理、`update()` 编排和发布。

## 4. 构造函数做了什么

### 4.1 参数和模式

构造函数读取 `chassis.yaml`。如果 `control_mode != "effort"` 就抛异常，因为 LQR 已经输出力矩，再插入速度 PI 会改变闭环模型。

### 4.2 加载多高度增益

默认读取六份增益：

```text
height_058.yaml、nominal.yaml、height_080.yaml
height_090.yaml、height_100.yaml、height_104.yaml
```X_pitch = [s, s_dot, pitch, pitch_rate,
           q_h_common, q_h_common_rate,
           q_k_common, q_k_common_rate]



`load_gain()` 强制校验：

1. Pitch 状态顺序：`[s, s_dot, pitch, pitch_rate, q_h_common, q_h_common_rate, q_k_common, q_k_common_rate]`；
2. Pitch 输入顺序：`[tau_w_common, tau_h_common, tau_k_common]`；
3. Roll 状态顺序：`[q_h_diff, q_h_diff_rate, q_k_diff, q_k_diff_rate]`；
4. Roll 输入顺序：`[tau_h_diff, tau_k_diff]`；
5. dt 和轮半径；
6. 当前 `robot_description` 的模型哈希；
7. K/X0/U0 的维度和有限性。

每份文件存成一个 `GainPoint`。`apply_gain_schedule(height)` 找到相邻工作点后，分别调用两个 LQR 类的
`interpolate()`，再用 `configure()` 装入当前高度的 K、X0、U0 和 `roll_per_q`。

运行时不解 Riccati 方程，只读离线 K。

### 4.3 ROS 接口

构造函数创建：

- 六个力矩 publisher；
- `/imu`、`/joint_states`、`/chassis/cmd_vel` 三个 subscriber；
- 动态参数回调；
- 周期 `0.001 s` 的控制定时器。

回调只缓存数据，控制计算全部集中在 `update()`。

## 5. 三个输入回调

### 5.1 `on_imu()`

从四元数计算 ZYX 欧拉角，把：

```text
orientation       → roll、pitch
angular_velocity.x → roll_rate
angular_velocity.y → pitch_rate
angular_velocity.z → yaw_rate
```

`pitch/pitch_rate` 进入 Pitch LQR，`yaw_rate` 进入偏航环。IMU 的 `roll/roll_rate` 不进入当前 Roll LQR，只用于倒地保护和几何一致性诊断。

### 5.2 `on_joint_state()`

代码按关节名寻找两个轮和四个腿关节。必须六个全部出现在同一帧，反馈才有效。

两轮折算为纵向状态：

```text
s     = r(q_wL + q_wR)/2
s_dot = r(dq_wL + dq_wR)/2
```

四个腿角和角速度原样缓存，稍后在 `update()` 中转换为共模/差模。

### 5.3 `on_cmd_vel()`

这里的 `Twist` 是项目内部协议：

```text
linear.x   前后归一化方向
angular.z  偏航归一化方向
linear.z   单拍事件：+1 长高，-1 变矮
```

`linear.z` 通过 `set_parameter("target_height_m", ...)` 更新高度，参数回调会检查可达范围。

## 6. 一拍 `update()` 的真实顺序

### 6.1 安全检查

`evaluate_safety()` 检查：

- IMU 和完整关节反馈是否到达/超时；
- 定时器是否严重超期；
- 状态是否含 NaN/Inf；
- `|pitch|`、`|roll|` 是否超过倒地阈值；
- 任一腿关节是否越过硬限位。

失败时 `enter_safe_state()` 清空遥控目标、位移原点、轮速和分配器历史，并发布六路零力矩。故障恢复后要持续健康一段时间才重新接管。

### 6.2 目标位置和身高

遥控超时后速度和偏航目标归零。位置参考按目标速度积分：

```cpp
teleop_.position += teleop_.velocity * dt;
```

因此前进时位置项不会一直把车拉回起点。

`LegHeightKinematics::move_towards()` 限制每拍高度变化，然后 `from_height()` 使用：

```text
h = 2L sin(alpha + q_h+)
q_k+ = -2q_h+
```

把身高转换成髋膝共模目标，并切换到对应身高的插值增益。

### 6.3 组装共模和差模

髋膝共模：

```text
q_h+ = (q_hL + q_hR)/2
q_k+ = (q_kL + q_kR)/2
```

髋膝差模：

```text
q_h- = (q_hL - q_hR)/2
q_k- = (q_kL - q_kR)/2
```

速度同样计算。

### 6.4 Pitch LQR

状态：

```text
X_pitch = [s-s0, s_dot, pitch, pitch_rate,
           q_h+, dq_h+, q_k+, dq_k+]
```

输入：

```text
U_pitch = [tau_w+, tau_h+, tau_k+]
```

代码：

```cpp
common = feedforward - control_sign * K_pitch * (X_pitch - Xref_pitch);
```

`feedforward` 先取增益文件的 U0，但髋膝两项会被 `height_gravity_effort()` 按当前目标腿姿重新计算。因此身高变化时重力前馈也跟着变化。

### 6.5 Roll LQR

状态：

```text
X_roll = [q_h-, dq_h-, q_k-, dq_k-]
```

输入：

```text
U_roll = [tau_h-, tau_k-]
```

代码：

```cpp
leg_difference = U0_roll - K_roll * (X_roll - X0_roll);
```

当前模型假设两轮贴地，roll 是左右腿高差的约束结果，不是独立状态。代码用：

```text
predicted_roll = roll_per_q * [q_h-, q_k-]
```

与 IMU roll 比较，仅做保护和诊断。

### 6.6 偏航环

偏航不是 LQR：

```cpp
differential = clamp(yaw_kp * (yaw_rate_target - yaw_rate));
```

它产生 `tau_w-`，只控制偏航角速度，不控制绝对航向角。

### 6.7 送入分配器

虚拟输入为：

```text
[tau_w+, tau_w-, tau_h+, tau_h-, tau_k+, tau_k-]
```

这六个量不是六个实体电机，而是三对执行器的共模/差模表示。

## 7. `TorqueAllocator` 的代码

文件：`project/node/chassis/torque_allocator.hpp`

### 7.1 共模优先恢复左右力矩

`allocate_pair()` 先夹住共模，再按左右剩余力矩空间夹差模，最后恢复：

```text
tau_left  = tau_common + tau_diff
tau_right = tau_common - tau_diff
```

因此髋膝饱和时优先保留 Pitch/身高共模，Roll 差模只能使用剩余余量。

### 7.2 软限位

进入软限位区后叠加：

```text
tau_recovery = kp * position_error - kd * velocity
```

这是输出侧保护力矩，不会修改 LQR 的目标状态。

### 7.3 成组缩放

软限位叠加后若超限，轮、髋、膝三对分别统一缩放左右两侧，保持左右比例。

变化率限制同样成组进行：比较当前目标与 `previous_effort_`，按同一系数向新目标移动。

最终数组顺序固定为：

```text
[左轮, 右轮, 左髋, 右髋, 左膝, 右膝]
```

## 8. 为什么代码是两个 LQR

左右对称且两轮贴地时，变换：

```text
q+ = (qL + qR)/2
q- = (qL - qR)/2
```

会把线性模型分成 Pitch 共模块和 Roll 差模块：

```text
A_total ≈ diag(A_pitch, A_roll)
B_total ≈ diag(B_pitch, B_roll)
```

如果做一个 12 状态、5 输入 LQR，且 Q/R 不放交叉权重，得到的 K 仍是两个 K 的块对角拼接。当前代码分开求解，在 `TorqueAllocator` 处处理共享实体关节的饱和冲突。

障碍接触、单轮离地或结构不对称后，这个解耦假设会失效。

## 9. 六个 `MotorNode`

入口：`project/node/motor/motor.cpp`
实现：`ros2_layer/node/motor/motor.hpp`

一个进程创建六个不同名字的节点：

```text
motor_left、motor_right
motor_left_hip、motor_right_hip
motor_left_knee、motor_right_knee
```

每个节点只管一个关节：订目标力矩、从 `/joint_states` 取速度、调用纯 C++ `modules::motor::Motor`、发布 `cmd_force`。

当前是 effort 模式，`Motor::update_effort()` 只做：

```text
命令年龄 <= 0.05 s 且数值有限 → 按 max_effort 限幅直通
否则                              → 输出 0
```

平衡算法不在 MotorNode。它是执行器适配层和最后一道超时/限幅护栏。

## 10. 其他节点

### `KeyboardNode`

`ros2_layer/node/keyboard/keyboard.hpp` 读取终端按键并发布 `/chassis/cmd_vel`。方向键产生前后/偏航目标，`=` 和 `-` 分别产生一拍身高事件。

### `ImuNode`

`ros2_layer/node/imu/imu.hpp` 可把原始角速度、加速度送进姿态融合模块并发布四元数和欧拉角，但当前 launch 没有启动它。

## 11. `generate_wheel_leg_lqr.cpp` 代码分析

这是离线程序，不是 ROS 节点。

### 11.1 输入

```text
argv[1]  URDF/xacro
argv[2]  输出增益 YAML
argv[3]  chassis.yaml，用于读取 Q/R
argv[4]  可选工作点身高
```

xacro 通过 `popen("xacro ...")` 展开，TinyXML2 再解析 link、joint、质量、惯量、COM 和关节原点。

### 11.2 Pitch 模型

广义坐标：

```text
q = [s, pitch, q_h+, q_k+]
```

`build_planar_robot()` 将 URDF 折算为机身、大腿、小腿、轮子四个平面刚体。`kinematics()` 计算 COM、COM 雅可比和角速度映射。

质量矩阵：

```text
M(q) = Σ[m JvᵀJv + I JwᵀJw]
```

`gravity_vector()` 解析计算 `G(q)=∂V/∂q`。`input_matrix()` 构造执行器到广义力的映射；共模左右各一个执行器，所以含系数 2，轮力矩还包含对小腿和车体的反作用。

静止工作点线性化：

```text
q_ddot = -M⁻¹(∂G/∂q)δq + M⁻¹Sδu
```

得到 8×8 A 和 8×3 B。

### 11.3 工作点、离散化和 K

高度工作点转换为：

```text
q_h+ = asin(h/(2L)) - alpha
q_k+ = -2q_h+
```

U0 由 `G(q0)=SᵀU0` 求出。

`discretize()` 用增广矩阵指数得到 Ad/Bd。`framework/algorithm/controller/lqr.hpp` 迭代离散 Riccati 方程：

```text
S = R + BᵀPB
K = S⁻¹BᵀPA
P_next = Q + AᵀP(A-BK)
```

### 11.4 Roll 模型

Roll 广义坐标：

```text
r = [q_h-, q_k-]
```

左右腿分别使用 `q+ + q-` 和 `q+ - q-`。`frontal_kinematics()` 在两轮贴地约束下由两腿高度差求 roll，并检查左右腿反推的机身原点一致。

Roll 输入映射是 `diag(2,2)`，因为左侧 `+tau-`、右侧 `-tau-` 对差模坐标共同做功。

配置中的六个 Roll Q 权重是：

```text
[roll, roll_rate, q_h-, dq_h-, q_k-, dq_k-]
```

LQR 实际只有四个腿差模状态。代码用 `roll_per_q=∂roll/∂[q_h-,q_k-]`，把前两个 roll 权重投影到 4×4 的差模 Q，再求 `K_roll`。

### 11.5 YAML 和检查

输出包含模型哈希、工作点、X0/U0、Pitch 与 Roll 的 A/B、Ad/Bd、K、Q/R、执行器禁用预测和 21 项检查结果。

运行时实际用于控制的是 K、X0、U0、`roll_per_q`。A/B 主要保存离线模型证据；`chassis` 虽然读取 Roll A/B，但不会用它们在线推进状态。

## 12. 测试代码

`test_leg_height.cpp` 验证高度与髋膝映射、`q_k=-2q_h`、可达范围夹紧和变化率。

`test_torque_allocator.cpp` 验证左右恢复、共模优先、成组限幅、变化率、软限位方向和非有限输入清零。

`test_runtime_lqr.cpp` 验证 Pitch/Roll 控制公式、工作点插值、Roll 几何预测和非法参数保护。

这些是纯 C++ 单元测试，不等于完整 Gazebo 闭环测试。

## 13. 代码为什么不会自动越障

`chassis` 只订阅：

```text
/imu、/joint_states、/chassis/cmd_vel
```

没有接触传感器、地形输入或卡滞状态机。碰到障碍后：

- Pitch 继续追速度、姿态和原身高；
- Roll 继续压制腿差模；
- 力矩过大只会被分配器裁剪；
- 没有代码会自动改 `target_height_m`。

所以卡在梯形障碍里没有自动缩腿，是控制目标和状态机根本不存在，不是 Roll 没运行。

## 14. 当前源码中容易误导的地方

1. `sim.launch.py` 的局部注释仍写 `chassis` 只发两个轮力矩，实际已经发六路。
2. `q_roll` 有六项，但 Roll LQR 只有四状态；roll/roll_rate 权重通过雅可比投影进去。
3. `chassis.yaml` 的 Q/R 只供离线工具使用，运行时改 Q/R 不会自动改变 K。
4. launch 读取 install 中的参数、模型和增益，修改 source 后需要重新构建同步。
